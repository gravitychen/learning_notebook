# LLM：从 Transformer 到训练、Agent 与 Harness

学习目标：理解大语言模型如何获得语言、指令、推理和工具使用能力，以及这些能力怎样与运行系统结合，成为 Codex、Claude Code 这类能持续做事的 Agent。

范围以 Transformer 之后为主；架构只做按需复习。当前是学习大纲，所有节点的掌握状态均为“未判断”，不预设已经掌握，也不代表完全不会。

2026-11-13 已依据 6 篇综述的 PDF 目录、分类图和相关正文进行覆盖核对，由 13 个主节点扩展为 19 个。参见 [综述 PDF 与版本索引](papers/README.md) 和 [分类方式、缺口及修改依据](survey-analysis.md)。这是围绕当前目标的可扩展学习树，不是“包含全部 LLM 概念”的声明。

## 先看三条线如何连接

模型训练更新权重，影响模型在给定上下文下会输出什么；Agent 运行把输出变为工具动作，并将环境反馈送回上下文；harness 负责组织这个循环、状态和执行边界。三者会相互影响，但不能互相替代。

修改提示词、AGENTS.md、CLAUDE.md、工具或记忆，通常不会直接更新模型权重。把任务轨迹收集为数据，再通过优化器更新权重，才进入这里讨论的模型训练过程。Codex 的公开资料也将开源 harness 与模型访问分开说明。[Codex 官方说明](https://developers.openai.com/blog/codex-as-a-platform)

编号用于后续引用和拆分节点；树表示内容归属，学习依赖另见下方路线，不表示所有方法必须依次执行。

│   │   ├── Tokenizer、Embedding、位置编码与 Decoder-only
│   │   ├── 因果注意力、输出概率：一次预测到底算了什么？

│   │   ├── 偏好数据与奖励模型：好回答如何被定义？
│   │   ├── 人类反馈与 AI 反馈；结果奖励、过程奖励与评分器偏差

│   ├── A6. 推理与部署：怎样在资源约束下生成？
│   │   ├── Prefill / Decode、KV cache：延迟与显存分别花在哪里？
│   │   ├── 批处理、注意力计算与系统吞吐优化
│   │   └── 量化、剪枝、蒸馏与推测解码：效率和质量如何权衡？
│   └── A7. 跨任务与分析视角（选修，不是额外必经训练阶段）
│       ├── 多模态：视觉语言对齐、感知与 GUI 操作的连接
│       ├── 继续训练、持续学习、灾难遗忘：怎样保留已有能力？
│       └── 数据、优化动态与机制分析：为什么学会，还是只记住模式？
├── B. Agent 学习：从输出答案到与环境交互
│   ├── B1. 最小 Agent：一项任务怎样被完成？

│   │   ├── 观察 → 决策 → 调工具 → 接收结果 → 再决策
│   │   ├── 工具调用的结构化参数与真实执行分别由谁负责？

## 建议学习路线与依赖

先快速浏览 C1–C3，观察一次自己熟悉的编码任务，把想解释的现象记下来；再学 A1–A4，理解训练与推理的边界。A3 的分布式训练可后置，不应成为理解 SFT 的前置障碍。

推理训练走 A4 → A5；工具训练走 A4 + B1 → B2；多步 Agent 训练走 A5 + B1 + B2 → B3。B4 的评测意识从第一个实验开始贯穿，而不是训练完才补。最后回到 C1–C4，连接模型能力与运行系统。RL 基础不足时，在 A4 的奖励、策略和优势处按需补学。

这不是固定生产配方：SFT、DPO、PPO、RLVR 等可以有不同组合，不能把它们排成所有模型都遵循的一条必经流水线。

新增分支是不同观察轴：A6 解释生成和部署成本；A7 是按需选修；B5 按能力、B6 按任务组织同一类 Agent，不是要重复学两套系统。C5、C6 与所有训练和运行节点交叉。覆盖映射详见 [综述对照表](survey-analysis.md)。扩散语言模型、SSM / 混合架构、专门多模态训练和更细的推理系统仍需专题综述补充，不将本次检索视为完整文献清单。

## 每个知识点以后怎样展开

沿用 ADMM 中已确认的方式：现象 / 含义 → 希望得到的能力 → 数据或反馈信号 → 如何计算 → 数学依据 → Python 与可观察结果。LLM 中优先解释计算或行为含义，不给算法量附会不存在的物理意义。

每个节点展开时记录：节点编号、前置依赖、掌握状态、解释、公式与张量形状、最小实验、评测结果、资料来源及仍未公开的问题。代码默认 Python，必要时对照产品实际语言。先用小实验理解机制，不把复现商业大模型设为学习前提。
