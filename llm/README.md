# LLM：从 Transformer 到训练、Agent 与 Harness

学习目标：理解大语言模型如何获得语言、指令、推理和工具使用能力，以及这些能力怎样与运行系统结合，成为 Codex、Claude Code 这类能持续做事的 Agent。

范围以 Transformer 之后为主；架构只做按需复习。当前是学习大纲，所有节点的掌握状态均为“未判断”，不预设已经掌握，也不代表完全不会。

## 先看三条线如何连接

模型训练更新权重，影响模型在给定上下文下会输出什么；Agent 运行把输出变为工具动作，并将环境反馈送回上下文；harness 负责组织这个循环、状态和执行边界。三者会相互影响，但不能互相替代。

修改提示词、AGENTS.md、CLAUDE.md、工具或记忆，通常不会直接更新模型权重。把任务轨迹收集为数据，再通过优化器更新权重，才进入这里讨论的模型训练过程。Codex 的公开资料也将开源 harness 与模型访问分开说明。[Codex 官方说明](https://developers.openai.com/blog/codex-as-a-platform)

## 知识树

编号用于后续引用和拆分节点；树表示内容归属，学习依赖另见下方路线，不表示所有方法必须依次执行。

```text
LLM：模型如何学会能力，又如何成为能做事的 Agent？
├── A. 模型训练：能力如何进入权重？
│   ├── A1. 从 Transformer 接到现代 LLM（按需复习）
│   │   ├── Tokenizer、Embedding、位置编码与 Decoder-only
│   │   ├── 因果注意力、输出概率：一次预测到底算了什么？
│   │   └── RoPE、长上下文、MoE：架构变化影响什么？
│   ├── A2. 预训练：为什么预测下一个 token 能学到能力？
│   │   ├── 文本与代码数据：清洗、去重、配比、数据泄漏
│   │   ├── Next-token prediction、交叉熵、反向传播
│   │   ├── 参数量、训练 token、算力与 scaling laws
│   │   └── 预训练与继续预训练：知识、能力和遗忘
│   ├── A3. 训练实作：怎样把目标变成一次权重更新？
│   │   ├── batch、序列打包、loss mask、梯度累积
│   │   ├── AdamW、学习率、混合精度、checkpoint
│   │   ├── 全量微调、LoRA、QLoRA：哪些参数在变？
│   │   └── 显存去向与分布式：DP / FSDP / TP / PP
│   ├── A4. 后训练：从续写文本到遵循指令与偏好
│   │   ├── SFT：指令数据、对话格式、只监督哪些 token？
│   │   ├── 偏好数据与奖励模型：好回答如何被定义？
│   │   ├── RLHF / PPO：奖励、策略、KL 约束如何配合？
│   │   └── DPO：直接利用偏好对，不必先拟合显式奖励模型
│   └── A5. 推理训练：怎样学会更有效地解题？
│       ├── 推理轨迹、冷启动 SFT、合成数据与蒸馏
│       ├── RLVR：用数学答案、程序测试等可验证信号给奖励
│       ├── GRPO：多条采样、组内比较、优势与策略更新
│       └── 训练时学习 vs 推理时多想、多采样、验证与搜索
├── B. Agent 学习：从输出答案到与环境交互
│   ├── B1. 最小 Agent：一项任务怎样被完成？
│   │   ├── 观察 → 决策 → 调工具 → 接收结果 → 再决策
│   │   ├── 工具调用的结构化参数与真实执行分别由谁负责？
│   │   └── 工作流与自主 Agent；何时继续、停止或请求帮助？
│   ├── B2. 工具能力怎样训练？
│   │   ├── 工具说明、调用示范、参数与返回结果的数据格式
│   │   ├── SFT / 模仿学习：何时调用、调用什么、怎样用结果
│   │   └── 无效参数、工具报错、失败恢复与新工具泛化
│   ├── B3. 多步 Agent 怎样训练？
│   │   ├── 可执行任务环境：初始状态、工具、测试、重置
│   │   ├── rollout 轨迹：观察、动作、反馈、最终产物
│   │   ├── 轨迹筛选、成功示范 SFT、偏好与交互式 RL
│   │   └── 稀疏奖励、信用分配、长程任务与 reward hacking
│   └── B4. 怎样判断它真的学会了？
│       ├── 留出任务与代码库、数据污染、跨环境泛化
│       ├── 成功率、测试覆盖、成本、延迟、重试预算
│       ├── 结果奖励、过程评价、verifier 各自的局限
│       └── 固定模型比较 harness；固定 harness 比较模型
└── C. 系统落地：怎样让能力稳定地发挥？
    ├── C1. Harness：包围模型的运行系统
    │   ├── Agent loop、工具调度、状态与事件记录
    │   ├── 上下文选择、检索 / RAG、压缩、记忆与进度交接
    │   ├── 沙箱、权限、审批、超时、重试与检查点
    │   └── skills、hooks、MCP、子 Agent：分别扩展哪一层？
    ├── C2. Codex：沿公开运行机制理解一次编码任务
    │   ├── 模型、CLI / IDE / App、harness 的职责边界
    │   ├── 读仓库 → 修改 → 执行测试 → 根据反馈继续
    │   └── AGENTS.md、上下文、工具与公开 harness 源码阅读
    ├── C3. Claude Code：用同一组问题对照观察
    │   ├── 收集上下文 → 采取行动 → 验证结果的循环
    │   ├── CLAUDE.md、skills、MCP、hooks 与子 Agent
    │   └── 长任务的上下文压缩、持久进度与会话恢复
    └── C4. 串起来做最小实验
        ├── 从一次真实工具调用追踪到模型输入输出
        ├── 用小模型 / 小数据观察 SFT 或 LoRA 的权重变化
        ├── 保存编码轨迹，设计测试反馈与留出评测
        └── 同一模型更换 harness，分析提升来自哪一层
```

## 建议学习路线与依赖

先快速浏览 C1–C3，观察一次自己熟悉的编码任务，把想解释的现象记下来；再学 A1–A4，理解训练与推理的边界。A3 的分布式训练可后置，不应成为理解 SFT 的前置障碍。

推理训练走 A4 → A5；工具训练走 A4 + B1 → B2；多步 Agent 训练走 A5 + B1 + B2 → B3。B4 的评测意识从第一个实验开始贯穿，而不是训练完才补。最后回到 C1–C4，连接模型能力与运行系统。RL 基础不足时，在 A4 的奖励、策略和优势处按需补学。

这不是固定生产配方：SFT、DPO、PPO、RLVR 等可以有不同组合，不能把它们排成所有模型都遵循的一条必经流水线。

## 每个知识点以后怎样展开

沿用 ADMM 中已确认的方式：现象 / 含义 → 希望得到的能力 → 数据或反馈信号 → 如何计算 → 数学依据 → Python 与可观察结果。LLM 中优先解释计算或行为含义，不给算法量附会不存在的物理意义。

每个节点展开时记录：节点编号、前置依赖、掌握状态、解释、公式与张量形状、最小实验、评测结果、资料来源及仍未公开的问题。代码默认 Python，必要时对照产品实际语言。先用小实验理解机制，不把复现商业大模型设为学习前提。
